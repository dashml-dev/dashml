  • • Dashboardy tworzone osobno dla każdej platformy
  • • Ten sam dashboard = 3× kod (Streamlit, Plotly, Looker)
  • • Brak jednolitego źródła prawdy
  • • Różne API, różne paradygmaty

✅ Rozwiązanie DashML

  • • Jeden plik .dashml → wiele platform
  • • Kompilator, nie runtime
  • • Deklaratywny YAML — czytelny dla ludzi i AI
  • • Pełna kontrola wersji (Git)
  • • Rozszerzalny system transformerów

DashML Manifesto

Zasady projektowe języka DashML

1

Kompilator, nie runtime

DashML generuje kod, nie wykonuje go. Brak zależności runtime.

2

DashML nigdy nie zwraca danych

Semantyka, nie DataFrame. Dane są pobierane przez wygenerowany kod.

3

Deklaratywny, nie imperatywny

Opisuje CO chcemy zobaczyć, nie JAK to zbudować.

4

Source-agnostic

CSV, SQL, BigQuery — źródło danych to konfiguracja, nie kod.

5

LLM- i human-friendly

YAML — prosty, przewidywalny, łatwy do generowania przez AI.

6

Backend-neutral, rozszerzalny

Microkernel + pluginy. Nowy backend = nowy transformer.

version: 0.1 title: "Sales Analytics Dashboard" style: "styles/dracula.dmls" data: type: bigquery path: products.orders_one_week pages: - id: "overview" title: "📊 Overview" charts: - id: "sales_by_state" type: "bar" title: "Sales by State" x: "state" y: "total_amount" agg: "sum" - id: "trends" title: "📈 Trends" charts: - id: "sales_over_time" type: "line" x: "order_date" y: "total_amount" agg: "sum"

Komendy CLI

# Generuj Streamlit python -m dashml_new.cli build dashboard.dashml \ --target streamlit --output app.py # Generuj Plotly HTML python -m dashml_new.cli build dashboard.dashml \ --target plotly --output dashboard.html # Utwórz dashboard w Superset python -m dashml_new.cli build dashboard.dashml \ --target superset --superset-user admin

Obsługiwane typy wykresów

Architektura systemu

Struktura projektu

dashml_new/ ├── core/ │ ├── engine.py # Orkiestracja │ ├── parser.py # YAML → dict │ ├── validator.py # Walidacja semantyczna │ └── types.py # TypedDict definitions │ ├── transformers/ │ ├── base.py # Interfejs Transformer │ ├── streamlit.py # → Python + Altair │ ├── plotly.py # → HTML + Plotly.js │ ├── observable.py # → HTML + D3 │ ├── superset.py # → Superset API │ └── registry.py # Plugin registry │ ├── cli.py # Interfejs CLI └── __init__.py

Microkernel + Plugins

Core (Microkernel)
Parser → Validator → Engine
Streamlit
Plotly
Observable
Superset

Transformery jako wymienne pluginy

Kluczowa zasada

Core nigdy nie wykonuje zapytań — generuje tylko kod, który sam pobierze dane w runtime.
